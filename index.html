Abstract

Action Chunking with Transformers (ACT) is a strong, lightweight baseline for imitation-based manipulation, but it conditions only on the current observation and has no mechanism for retaining information from earlier in an episode. It fails on tasks where the correct action depends on something no longer visible: a reference object that was hidden, a button already pressed, a block that was moved. Policies that add memory often rely on a vision-language model to summarize the history as selected frames and text, which is costly at inference time and loses information.

LEO augments ACT with explicit memory mechanisms learned from expert demonstrations alone, without a vision-language model. The first is a gated memory in ACT's decoder, following Gated Memory Policy: past frames are cached as one token each and read through cross-attention. The second, ACT-SMT, maintains a fixed-size memory state learned with Supervised Memory Training: a full-history Transformer teacher produces memory targets, and a small recurrent updater learns one-step transitions without backpropagation through time. The frozen updater runs online and feeds its memory to ACT as extra tokens.

On RMBench, a benchmark of nine memory-dependent dual-arm tasks, the always-on cross-attention memory raises success from 0 to 100 of 100 rollouts on rearrange_blocks and from 32 to 68 on put_back_block (training seed 0). The learned gate lowers both, and a control that remembers only past joint positions and time does as well as or better than image memory. No variant solves observe_and_pickup, where ACT-SMT has its only evaluation so far (6 of 100).

Method

Baseline

ACT

Predicts the next 50 actions from the current images and joint state. We run the stock RMBench code and our own re-implementation, which the memory variants build on.

Memory variant

Gated memory

The first frame and every fourth past frame are cached as one token each and read by a cross-attention sublayer in the decoder. We test it always on, switched per step by a learned gate, with the first frame only, and with the images removed.

Memory variant

ACT-SMT

A fixed-size memory zt summarizes the episode. A teacher encoder sees the full history; an updater learns to reproduce its next memory from the current one and the new frame. Only the updater runs at test time.

ACT-SMT pipeline. Outlined boxes are added by LEO. The teacher and decoder are used only during training.

What the rollouts show

  • Always-on memory fixes the two tasks that depend on one earlier event. On rearrange_blocks it places the first block and presses the button exactly once in all 100 rollouts. Plain ACT never places the first block.
  • The learned gate hurts. On rearrange_blocks the gate was on for about 7% of steps and the policy pressed the button in 12 of 100 rollouts. On put_back_block the gated policy succeeds only when the block starts on the right mat.
  • The gain does not need images. The arm-history control, which remembers only past joint positions and time, reaches 100 on both tasks.
  • Without memory, ACT guesses one answer. On put_back_block plain ACT returns the block to the back mat in every rollout, so its 32 successes are exactly the episodes that started there. Always-on memory returns the block to the correct mat in all 68 rollouts where it moves the block, and never starts on the 32 back-mat episodes.
  • observe_and_pickup is unsolved. No model lifts the target in more than 6 of 100 rollouts.
  • Seeds matter. Stock ACT scores 38, 0 and 0 on rearrange_blocks and 0, 49 and 0 on put_back_block across training seeds 0 to 2. Seeds 1 and 2 of the memory variants are not finished.
